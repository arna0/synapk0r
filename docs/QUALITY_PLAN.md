# Simulator quality implementation

The accepted review is the implementation brief. Keep the existing browser and Flutter entry points and Three.js visual language.

1. Use measured exercise results in aggregate scores. Report assistance, evidence, practice targets and per-profession progress. Preserve older saved results as legacy observations.
2. Rotate coherent IT incidents with different evidence and repairs, validate recovery and stop restoration timing at recovery. Keep scenario rules independently testable.
3. Consolidate objectives, support keyboard and assistive technology in mini-games and make Safety escalation meaningful.
4. Collect private feedback by default with explicit optional public publication. Preserve consent during offline retries.
5. Replace unconfirmed scanned assets with procedural geometry and document asset provenance. Mark the Doctor exercise as awaiting practising-clinician review.
6. Verify through unit/API tests and ordinary browser playthroughs, including deliberate mistakes, replay, keyboard, small screens and both API implementations.

Clinical approval, source licensing decisions by the owners, and competition outcomes cannot be supplied by software changes. Record their status accurately.
