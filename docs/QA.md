# Подготовка к вопросам жюри

Положение, п. 5.3: команда должна понимать архитектуру своего решения, объяснять роль инструментов и отделять своё от стороннего. Этот файл — шпаргалка, чтобы каждый в команде мог ответить за 30 секунд.

## Как устроен проект за 1 минуту

1. **Браузер (`frontend/`).** Обычные HTML, CSS и JavaScript без сборщика. Three.js рисует 3D-сцену из простых фигур (кубы, цилиндры), текстуры экранов рисуются на `<canvas>`.
2. **Игровой цикл (`engine.js`).** 60 раз в секунду: двигаем игрока по WASD, поворачиваем камеру мышью, пускаем луч из центра экрана (raycast) и смотрим, на какой предмет наведён прицел.
3. **Модули.** «Инженер ТБ» и «Бариста» написаны отдельными файлами. «IT-инженер» и «Врач» — на общем движке `scenario.js`: модуль — это описание (сцена, 6 шагов, 2 решения, тексты отчёта), а движок сам ведёт гид, HUD, проверку порядка и отчёт.
4. **Оценка — на клиенте, по правилам.** Шаги: 100 % − 5 % за каждый клик не по тому предмету. Итог: 35 % шаги + 40 % решение на знания + 25 % решение на общение, от 20 до 99.
5. **ИИ (`backend/`).** Node.js + Express. Клиент отправляет балл, метрики и журнал действий на `POST /api/report`. Сервер проверяет данные и просит Claude написать разбор строго по JSON-схеме. Ключ API — только на сервере. Нет ключа или ошибка — работает разбор по правилам (`rules.js`).
6. **Анкета и язык.** `survey.js` — 8 вопросов после отчёта, `career.js` — путь в профессию в РК, `i18n.js` — перевод интерфейса на казахский по исходной русской строке.

## Как пройти по коду нового модуля (для вопроса «покажите, как это работает»)

Откройте `frontend/js/it.js`, внизу — `registerScenario({...})`:
- `steps` — 6 шагов: `id` (какой предмет нажать), `how`/`why` (тексты гида), `run(done)` (анимация и что меняется на экранах);
- `decisions` — 2 вопроса внизу экрана, у каждого варианта свой балл (100 — лучший);
- `report` — подписи метрик и тексты вердикта.

В `scenario.js`: `handleScenarioClick` сравнивает нажатый предмет с текущим шагом (не тот — промах, `state.misclicks++`), `showScenarioReport` считает балл и отправляет отчёт на бэкенд.

## Вероятные вопросы и ответы

- **Где здесь ИИ и зачем он, если балл по правилам?** Балл должен быть проверяемым и одинаковым для всех — поэтому правила. ИИ объясняет результат человеческим языком, опираясь на журнал действий: что получилось, что улучшить, подходит ли профессия.
- **Что сделали вы, а что стороннее?** Своё: сцены, управление, движок сценариев, правила оценки, гид, бэкенд, промпт и схема, анкета, перевод. Стороннее: Three.js (рендер), Express, Flutter, Google Fonts, Claude API. При разработке модулей IT, Врач и движка сценариев использовали ИИ-ассистента Claude — это указано в README.
- **Что было до хакатона?** Базовый прототип (коммиты 14–16.09, история не переписана). За время этапа — всё из раздела 8 README.
- **Как вы проверили, что это нужно?** Кабинетное исследование по Казахстану, технические испытания и тест на 7 людях: 86 % прошли без помощи, 100 % узнали новое. Гипотеза H1 не подтвердилась — честно говорим почему (половина участников уже студенты).
- **Почему не VR?** Шлем стоит дорого и его нет в школах. Браузер есть везде, включая телефон.
- **Как добавить профессию?** Один файл с `registerScenario`, подключить в `index.html`, добавить модуль в `backend/src/validate.js` и текст для ИИ в `feedback.js`.
- **Какие данные вы собираете?** Никаких персональных: нет регистрации, имени, почты. Журнал действий и ответы анкеты анонимны. Анкета хранится на устройстве и (если есть сервер) в файле на сервере.
- **Что с безопасностью?** Ключ API только на сервере; все входные данные проверяются (`validate.js`), лимит запросов с одного IP, защитные HTTP-заголовки, ограничение размера запроса 32 КБ, автотесты в CI.
- **Работает без интернета?** Да: Three.js лежит в репозитории, игра запускается с локального сервера (`npm start`). Без интернета не будет только ИИ-разбора и шрифтов Google.
- **Как зарабатывать?** Ученикам бесплатно; школам — подписка с кабинетом учителя; работодателям — лицензия со своими сценариями. Это гипотеза, пилот в школе — следующий шаг.
- **Медицинский сценарий корректен?** Он учебный и упрощённый, это написано на вводном экране. До пилота — проверка практикующим врачом.
